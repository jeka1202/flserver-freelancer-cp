FL ControlPanel Warehouse Internal Transfers v17

Главное уточнение логики:
- Передача между пилотами выполняется только склад -> склад.
- Нельзя передать предмет сразу на корабль другого пилота.
- Склад получателя создаётся/пополняется во внутренней SQLite-БД.
- .fl файлы, трюм корабля и FLHook при таких операциях не используются.

Текущая модель:
1. Трюм корабля
   - игровое состояние пилота;
   - читается из .fl;
   - изменять его будем только отдельными операциями через FLHook, когда это понадобится.

2. Склад базы
   - наша внутренняя система;
   - личный склад конкретного персонажа на конкретной базе;
   - ключ: account_id + character_file + location_hash.

3. Передача
   - списывает предмет со склада отправителя;
   - добавляет предмет на склад получателя на этой же базе/планете;
   - если склада получателя не было, он создаётся автоматически.

4. Крафт
   - тоже работает внутри нашей БД;
   - берёт ресурсы со склада;
   - результат кладёт обратно на склад.

Интерфейс:
- Из окна предмета убрана кнопка "На корабль", чтобы не путать складские операции с игровым трюмом.
- Остались:
  - Удалить
  - Передать на склад
  - Свойства

Запуск:
  py .\account_panel.py --accounts "c:\users\jeka1202\documents\my games\freelancer\accts\multiplayer" --ioncross "e:\[game]\freelancer\ioncross"

Импорт свойств предметов:
  py -m fl_panel.import_item_assets --data "e:\[game]\freelancer\data"
